Conteúdo abordado

Qualidade e testes

Os pontos principais da matéria, em linguagem direta e ligados ao desenvolvimento de aplicações web.

01

Qualidade de software

Qualidade vem de requisitos claros, código organizado, revisão, testes e melhoria contínua. Não é algo colocado apenas no final.

02

Teste de software

É executar e verificar partes do sistema para descobrir defeitos e confirmar se o comportamento esperado foi atendido.

03

Por que testar

Testar reduz o risco de falhas, retrabalho e perda de confiança. Quanto antes um erro aparece, mais simples costuma ser a correção.

04

Confiabilidade e defeitos

Um software confiável se comporta de forma previsível. Defeitos não somem totalmente, mas podem ser prevenidos, encontrados e controlados.

05

Tipos e níveis

Os testes podem avaliar unidade, integração, sistema e aceitação, além de aspectos funcionais e não funcionais.

06

Funcional x unidade

O teste funcional observa uma regra do ponto de vista do uso; o teste de unidade isola uma classe ou método para validar uma parte pequena.

07

Equipe e processo

Qualidade é responsabilidade de todos. Testes acompanham análise, desenvolvimento, integração e entrega, em vez de formar uma etapa separada.

08

Ferramentas e automação

Ferramentas ajudam quando existem testes repetitivos, regressões frequentes e necessidade de retorno rápido. Nem todo teste precisa ser automatizado.

09

Automatizar com critério

Vale automatizar cenários estáveis, importantes e executados muitas vezes. Exploração, usabilidade e situações raras ainda pedem avaliação humana.

Testes de Integração

Conteúdo teórico, prática desenvolvida e avaliação quantitativa no ecossistema Spring Boot.

Base teórica

O que o teste valida

Teste de integração verifica se diferentes partes reais do sistema funcionam juntas. Em uma aplicação Spring Boot, isso pode envolver controller, service, repository, serialização JSON, configuração do contexto e banco de dados de teste.

Diferente do teste unitário, que observa uma unidade pequena de código de forma isolada, o teste de integração avalia o fluxo entre camadas e ajuda a encontrar problemas de configuração, persistência e comunicação interna.

Programa prático

API de Produtos

O programa desenvolvido implementa uma API REST simples para cadastro e consulta de produtos de uma loja virtual. O teste principal envia uma requisição para POST /produtos, passa pelas camadas da aplicação e confirma a gravação no banco H2.

Comentário pessoal

Testar dá segurança para mudar.

O que mais ficou claro para mim é que teste não serve só para provar que algo funciona. Ele ajuda a entender melhor a regra, encontrar erros antes da entrega e alterar o código com menos medo de quebrar o que já estava pronto.

No trabalho de integração, a prática mostrou que a confiança aumenta quando o teste percorre o caminho completo da API, desde a requisição HTTP até a persistência no banco de teste.
